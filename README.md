# Job Hunter Telegram Bot

Интерактивный Telegram-бот для автоматического поиска и отклика на вакансии на **7 платформах** с поддержкой двух режимов работы (Авто-пилот и Ручной разбор) и управлением прямо из чата.

### Поддерживаемые площадки

| Площадка | Тип доступа | Авто-отклик | Примечание |
|---|:---:|:---:|---|
| **HeadHunter (hh.ru)** | OAuth API | ✅ Да | Основная платформа |
| **Зарплата.ру** | OAuth API (единое с HH) | ✅ Да | Тот же токен, что и HH |
| **SuperJob** | OAuth API | ✅ Да | Требует отдельный API-ключ |
| **Хабр Карьера** | Web scraping (JSON/XHR) | ❌ Только просмотр | Вакансии показываются в чате |
| **Авито Работа** | Web scraping (HTML) | ❌ Только просмотр | Вакансии показываются в чате |
| **Freelance.ru** | Web scraping (HTML) | ❌ Только просмотр | Проекты показываются в чате |
| **Workzilla** | Web scraping (HTML) | ❌ Только просмотр | Задания показываются в чате |

## 📦 Предварительные требования и зависимости

### Вариант 1. Запуск через Docker (рекомендуется)
Если вы запускаете проект через Docker, **устанавливать Python, библиотеки и PostgreSQL на свой компьютер не нужно**. Достаточно иметь:
- **Docker Desktop** (для Windows/macOS) или `docker` + `docker compose` (для Linux).

### Вариант 2. Локальный запуск (без Docker)
- **Python 3.14+** (или 3.12+).
- **PostgreSQL 16** (локально или через `docker compose up -d db`).
- Установка зависимостей проекта:
  - **Через `uv` (быстро):** `uv sync --all-groups`
  - **Через `pip`:** `pip install -r requirements.txt`

## ⚙️ Переменные окружения (.env)

Создайте файл `.env` в корне проекта (на основе шаблона `.env.example`):

### Обязательные переменные

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от `@BotFather` |
| `OWNER_CHAT_ID` | Числовой Telegram ID владельца (узнать: [@userinfobot](https://t.me/userinfobot)) |
| `DATABASE_URL` | Подключение к PostgreSQL: `postgresql+asyncpg://postgres:postgres@db:5432/jobhunter` |
| `HH_ACCESS_TOKEN` | OAuth Access Token API HeadHunter (см. [launch_guide.md](launch_guide.md)) |
| `HH_RESUME_ID` | 32-символьный хэш резюме с HeadHunter |

### SuperJob (опционально)

| Переменная | Описание |
|---|---|
| `SUPERJOB_SECRET_KEY` | API Secret Key от SuperJob |
| `SUPERJOB_ACCESS_TOKEN` | OAuth Access Token SuperJob |
| `SUPERJOB_RESUME_ID` | Числовой ID резюме на SuperJob |

### Переключатели площадок

| Переменная | По умолчанию | Описание |
|---|:---:|---|
| `ENABLE_HH` | `true` | HeadHunter (hh.ru) |
| `ENABLE_ZARPLATA` | `true` | Зарплата.ру |
| `ENABLE_SUPERJOB` | `false` | SuperJob (требует отдельный API-ключ) |
| `ENABLE_HABR` | `false` | Хабр Карьера (только просмотр вакансий) |
| `ENABLE_AVITO` | `false` | Авито Работа (только просмотр вакансий) |
| `ENABLE_FREELANCE_RU` | `false` | Freelance.ru (только просмотр проектов) |
| `ENABLE_WORKZILLA` | `false` | Workzilla (только просмотр заданий) |

### Фильтры поиска

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SEARCH_QUERY` | `Оператор чата OR Менеджер OR Поддержка` | Начальный поисковый запрос |
| `REMOTE_ONLY` | `true` | Искать только удаленную работу |
| `POLL_INTERVAL_SECONDS` | `300` | Интервал между циклами поиска (сек) |
| `DEFAULT_COVER_LETTER` | `Здравствуйте! ...` | Текст сопроводительного письма |

> **ВАЖНО для существующих установок:**
> После обновления добавьте переменную `OWNER_CHAT_ID` (или оставьте `TELEGRAM_CHAT_ID` — поддерживаются оба имени благодаря `AliasChoices`). Без указания ID владельца бот не запустится в целях безопасности.

## 🗄️ Миграции базы данных (Alembic)

Для применения миграций на **любой** базе данных (как на чистой, так и на существующей рабочей базе со старыми таблицами) используется **одна команда**:

```bash
alembic upgrade head
```

- **Идемпотентность:** миграция `001_initial_processed_items` автоматически проверяет наличие таблицы `processed_items` через инспектор базы данных. Если таблица уже создана, создание пропускается без ошибок. Выполнять `alembic stamp` вручную **не требуется**.
- **Безопасность данных:** откат миграции `001` (`downgrade`) не удаляет таблицу `processed_items`, гарантируя сохранность истории дедупликации откликов.

## 💬 Команды управления ботом

Доступ к командам разрешён строго владельцу (`OWNER_CHAT_ID`), сообщения от других пользователей молча игнорируются:

- `/start` — приветствие и инициализация профиля настроек.
- `/status` — просмотр текущего статуса: активен/пауза, режим (Авто / Ручной), поисковый запрос, стоп-слова и обязательные слова (`любое из слов`).
- `/mode` — переключение между авто-откликом и ручным разбором карточек с кнопками.
- `/pause` — приостановка фонового поиска и откликов.
- `/resume` — возобновление поиска вакансий.
- `/query <текст>` — изменение поискового запроса (пустой запрос запрещен).
- `/keywords <слово1, слово2>` — список обязательных ключевых слов (логика: достаточно совпадения *любого из слов*).
- `/exclude <слово1, слово2>` — список стоп-слов (вакансии с этими словами отсекаются).
- `/remote` — переключение фильтра «только удалённая работа».
- `/search` — внеочередной принудительный запуск цикла поиска.

## 🚀 Запуск проекта

### 1. Запуск через Docker Compose (24/7 в фоне, рекомендуется)

Миграции накатываются автоматически перед запуском приложения, а служба настроена на автоматический перезапуск при сбоях (`restart: always`):

```bash
# Сборка и запуск в фоновом режиме
docker compose up -d --build

# Просмотр логов в реальном времени
docker compose logs -f worker

# Проверка статуса контейнеров
docker compose ps
```

### 2. Локальный запуск (без Docker)

```bash
# 1. Установка зависимостей (через uv или pip)
uv sync
# или: pip install -r requirements.txt

# 2. Накат миграций
uv run alembic upgrade head

# 3. Запуск приложения
uv run python -m app.main
```

### Интеграционные тесты на PostgreSQL
Для проверки работы на реальном экземпляре PostgreSQL:

```powershell
# 1. Запуск тестового контейнера Postgres на порту 5433
docker compose -f docker-compose.test.yml up -d

# 2. Установка переменной тестовой БД (PowerShell)
$env:TEST_DATABASE_URL="postgresql+asyncpg://postgres:postgres@localhost:5433/jobhunter_test"

# 3. Запуск интеграционных тестов
uv run pytest -m integration

# 4. Остановка тестового контейнера
docker compose -f docker-compose.test.yml down -v
```

Подробное пошаговое руководство по получению всех токенов и ключей находится в файле [launch_guide.md](launch_guide.md).
