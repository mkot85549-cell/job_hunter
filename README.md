# Job Hunter Telegram Bot

Интерактивный Telegram-бот для автоматического поиска и отклика на вакансии на платформах **HeadHunter (hh.ru)** и **Zarplata.ru** с поддержкой двух режимов работы (Авто-пилот и Ручной разбор) и управлением прямо из чата.

---

## Переменные окружения (.env)

Создайте файл `.env` в корне проекта (на основе `.env.example`):

| Переменная | Обязательная | Описание |
|---|:---:|---|
| `BOT_TOKEN` | Да | Токен Telegram-бота от `@BotFather` |
| `OWNER_CHAT_ID` | Да | Telegram ID владельца бота (число). Доступ разрешен только этому ID. |
| `DATABASE_URL` | Да | Строка подключения к PostgreSQL: `postgresql+asyncpg://postgres:postgres@db:5432/jobhunter` |
| `HH_ACCESS_TOKEN` | Да | OAuth Access Token API HeadHunter |
| `HH_RESUME_ID` | Да | ID резюме на HeadHunter для отправки откликов |
| `SEARCH_QUERY` | Нет | Начальный поисковый запрос (по умолчанию: `Оператор чата OR Менеджер OR Поддержка`) |
| `REMOTE_ONLY` | Нет | Искать только удаленную работу (`true`/`false`, по умолчанию: `true`) |
| `POLL_INTERVAL_SECONDS` | Нет | Интервал между циклами поиска в секундах (по умолчанию: `300`) |
| `DEFAULT_COVER_LETTER` | Нет | Текст сопроводительного письма по умолчанию |

> **ВАЖНО для существующих установок:**
> После обновления добавьте переменную `OWNER_CHAT_ID` (или оставьте `TELEGRAM_CHAT_ID` — поддерживаются оба имени благодаря `AliasChoices`). Без указания ID владельца бот не запустится в целях безопасности.

## Миграции базы данных (Alembic)

Для применения миграций на **любой** базе данных (как на чистой, так и на существующей рабочей базе со старыми таблицами) используется **одна команда**:

```bash
alembic upgrade head
```

- **Идемпотентность:** миграция `001_initial_processed_items` автоматически проверяет наличие таблицы `processed_items` через инспектор базы данных. Если таблица уже создана, создание пропускается без ошибок. Выполнять `alembic stamp` вручную **не требуется**.
- **Безопасность данных:** откат миграции `001` (`downgrade`) не удаляет таблицу `processed_items`, гарантируя сохранность истории дедупликации откликов.

## Команды управления ботом

Доступ к командам разрешён строго владельцу (`OWNER_CHAT_ID`), сообщения от других пользователей молча игнорируются:

- `/start` — приветствие и инициализация профиля настроек.
- `/status` — просмотр текущего статуса: активен/пауза, режим (Авто / Ручной), поисковый запрос, стоп-слова и обязательные слова (`любое из слов`).
- `/mode` — переключение между авто-откликом и ручным разбором карточек с кнопками.
- `/pause` — приостановка фонового поиска и откликов.
- `/resume` — возобновление поиска вакансий.
- `/query <текст>` — изменение поискового запроса (пустой запрос запрещен).
- `/keywords <слово1, слово2>` — список обязательных ключевых слов (логика: достаточно совпадения *любого из слов*).
- `/exclude <слово1, слово2>` — список стоп-слов (вакансии с этими словами отсекаются).
- `/remote` — переключение фильтра «только удалённая работа».
- `/search` — внеочередной принудительный запуск цикла поиска.

## Запуск проекта

### 1. Запуск через Docker Compose (рекомендуется)

Миграции накатываются автоматически перед запуском приложения:

```bash
docker compose up -d --build
```

### 2. Локальный запуск через `uv`

```bash
# Установка зависимостей
uv sync

# Применение миграций
uv run alembic upgrade head

# Запуск приложения
uv run python -m app.main
```

## Тестирование

### Unit-тесты
```bash
uv run pytest
```

### Интеграционные тесты на PostgreSQL
Для проверки работы на реальном экземпляре PostgreSQL:

```bash
# 1. Запуск тестового контейнера Postgres на порту 5433
docker compose -f docker-compose.test.yml up -d

# 2. Установка переменной тестовой БД (PowerShell)
$env:TEST_DATABASE_URL="postgresql+asyncpg://postgres:postgres@localhost:5433/jobhunter_test"

# 3. Запуск интеграционных тестов
uv run pytest -m integration

# 4. Остановка тестового контейнера
docker compose -f docker-compose.test.yml down -v
```
